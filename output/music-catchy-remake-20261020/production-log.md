# Production log — v2 重做（Opus 5.5 主创 / 实现；Codex：TTS 资产、M4 渲染、核验）

## 2026-10-20
1. **接手状态**：上一制作阶段的 Opus 留下了 `narration-request.json`、`src/timeline.js`（v1 式的 lane / pads 结构）和 `src/narration.js`（估计值），以及音乐分析与重复度数据。3D 场景、角色、镜头和合成都还没写。
2. **方向**：比较了三个方向（v1 频谱球 / 鼓机脑子 / 踩拍之路），选了**踩拍之路**。理由：三个解释都能做成同一世界里可比较的状态变化（间距、厚度、虚线框对实物、颜色），并且有空间层次与角色动作。`timeline.js` 按这个方向重写（石头路径、重复组、镜头分段）。
3. **口播第 2 批**：按科学修订改 4 句——L04“拍子稳，更容易跟着点头”（去掉因果），L05“第二，低音先变薄”（实测是变薄），L07“期待和意外，都会影响好不好听”（一般规律，角标“和弦实验，非本曲”），L08 缩成“第三，重复”（为 L09 让出时间）。Codex 合成后，11 句全部按真实时长排入，无重叠，三段体验窗口内不说话。
4. **实现**：`world.js`（程序建模的角色、圆角石头、虚线框、天空、频谱光柱、浮尘、网格、冲击环、③ 的弧线、泛光）和 `film.js`（跳跃弧线和挤压拉伸、落石、下沉、14 个镜头、2D 层和逐词字幕）。
5. **服务器单帧审看**（SwiftShader）中修过的问题：
   - 耳机头带横穿脸 → 改成从一侧耳朵到另一侧；
   - drop 帧泛光过曝 → 降低巨石发光、泛光、角色补光（保留冲击环和震动）；
   - 石头像发白的立方块 → 改成较暗的瓷质厚片；
   - 正面量尺被上一行的巨石挡住 → 走过的整行沉入深处，③ 时整首歌再浮起；
   - 对比不清 → 加大巨石，“猜的”小框放在巨石顶上；
   - 研究柱状图和小节网格重叠 → 鸟瞰下移、图移到左上；
   - 答案段只看到背影 → 改成从前方拍；
   - 第 0 帧没有问题 → 标题两行从第 0 帧就完整出现；
   - 量尺有跨行的悬空标签 → 只连同一行的相邻石头。
   - 采纳 Codex 的精度建议：角标“石块 = 节拍示意 · 小人是比喻”（73 块里 2 块没有吸附到起音）；“同色 = 相似的小节”；颜色角标注明是频谱相似度，不是逐音比对。
6. **混音**（`tools/mix.py`）：
   - 人声整体加 7.4 dB（目标 −16 LUFS），只对人声做峰值限制（−3 dBFS；TTS 人声的峰值比响度高约 19 dB）；
   - 音乐只在说话时按句压低：让该句下的音乐比人声低 5 LU，压低量限制在 4–12 dB，同时 2.4 kHz 处 −4 dB；
   - 三段体验窗口与 master 的音乐逐样本一致（只差全局 −1.1 dB 的静态修整），≈ −12.5 LUFS；
   - master −14.3 LUFS / −1.5 dBTP。
   - 调试中修掉两个我自己的错：测峰时用了会削波的 24-bit 临时文件；压低包络的整数索引丢样本，导致约一半样本没被压低。
7. **核验**：`verify.mjs` 改为适合有旁白的片子（不做“整片对原曲”的相关；只在 music-only 窗口对原曲；检查人声每句都有能量、句间完全静音）。服务器上用黑场占位画面测试：音频相关检查全部通过（drop 窗口对原曲 r ≥ 0.999、时延 0 ms）。
